\section{Introduction}

Extended tracts of homozygosity in individual genomes manifest as a result of haplotypes inherited identical by descent (IBD) from both biological parents. These runs of homozygosity (ROH) are important genomic features, with their length distributions and genomic locations informative about population history and useful for the mapping of recessive loci contributing to Mendelian and complex diseases. However, precisely because the length distribution of ROH is affected by population history, a simple one-size-fits-all genotype-counting approach to inferring ROH in multiple populations is ill-advised. Here, we present a model-based method and accompanying software package for inferring ROH in microarray-derived SNP genotype that incorporates population-specific parameters and genotyping error rates as described in \cite{PembertonEtAl12:AJHG}. Version 1.1.0 added a method for reweighting LOD scores by gaps between SNPs, the option to report ROH lengths in cM, and the ability to provide per-genotype error rates.  Version 2.0.0 reads VCF input directly (Section~\ref{sec:vcf}), analyses each population in a file separately rather than pooling them (Section~\ref{sec:multipop}), calls runs on the shared sex chromosome instead of treating it as an autosome (Section~\ref{sec:sexchr}), and counts classified genotypes inside and outside the calls (Section~\ref{sec:features}).  It also identifies the two modes of the LOD score density by their sign when it chooses the automatic cutoff, can choose that cutoff within strata of individuals of similar depth (Section~\ref{sec:stratify}), drops masked regions (Section~\ref{sec:refbias}), and reports the evidence available for each individual (Section~\ref{sec:ind}).  It is not backward compatible with files written by v1.1.6a, and the change log in Section~\ref{sec:changelog} describes the differences.

If you use GARLIC please cite the following articles,

\noindent ZA Szpiech, A Blant, TJ Pemberton. (2017) GARLIC: Genomic Autozygosity Regions Likelihood-based Inference and Classification. Bioinformatics doi: 10.1093/bioinformatics/btx102.
\\\\
TJ Pemberton, et al. (2012) Genomic patterns of homozygosity in worldwide human populations. American Journal of Human Genetics, 91, $275-292$.

\section{Obtaining {\tt GARLIC}}

Windows users no longer need {\tt ann\_figtree\_version.dll} or {\tt figtree.dll} alongside {\tt garlic.exe}, because {\tt GARLIC} no longer links FIGTree or ANN.

{\tt GARLIC} pre-built binaries and source code are available at {\tt https://github.com/szpiech/garlic}.  To compile from source, change to the {\tt src/} directory and type {\tt make}, which detects the platform from {\tt uname}, so no editing is needed.  The only external dependency is the zlib library ({\tt http://www.zlib.net/}), which the system provides on Linux and macOS.  Threading uses {\tt std::thread} from the C++11 standard library, for which the Makefile passes {\tt -pthread} on Linux, and GNU GSL and FIGTree are no longer used.  On Windows, {\tt GARLIC} is built in an MSYS2/MinGW environment ({\tt https://www.msys2.org/}) with zlib from the MinGW toolchain ({\tt mingw-w64-x86\_64-zlib} under MSYS2's MINGW64), and the MinGW GCC must be configured with the POSIX threading model, which is what provides {\tt std::thread} on that platform.

\section{Basic Usage}

A run needs genotypes, an assembly, a genotyping error rate and a name for the
output.  The bundled example is human SNP-array data on hg18 coordinates:
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 30 --auto-winsize --out example}
~\\\\
\noindent A priori we do not know how large to make the window, so this uses
the built-in search ({\tt --auto-winsize}).  The search begins at the
{\tt --winsize} value and increases, so a starting size is required, and
{\tt --auto-winsize} alone is an error.  All output is named starting with
{\tt example} ({\tt --out example}).  On this data the search settles on 50
SNPs, and the run writes:

\begin{itemize}
\item {\tt example.log}, the run's parameters and progress;
\item {\tt example.params.json}, every flag's effective value together with
      the window size, LOD cutoff, size-class boundaries and random seed the
      run resolved, which can be replayed with {\tt --load-params};
\item {\tt example.freq.gz}, the allele frequencies used;
\item {\tt example.50SNPs.kde}, the LOD score density at the selected window
      size, which is part of the file name;
\item {\tt example.roh.bed}, the calls.
\end{itemize}

\noindent An {\tt example.error} file appears beside these only if something is
actually written to it.  Adding {\tt --froh} writes {\tt example.froh.tsv}, one
row per individual giving the autozygous total and the fraction of the genome
it covers.

The same run from a VCF needs no {\tt --tfam}, since a VCF names its samples,
but it does need {\tt --pop} if the samples are not all one population:
~\\\\
{\tt garlic --vcf cohort.vcf.gz --pop cohort.pop --build hg38 --error 0.001 --winsize 30 --auto-winsize --out cohort}
~\\\\
\noindent Both readers accept gzipped input directly, and a VCF may also be
BGZF.  See Section~\ref{sec:vcf} for what {\tt garlic} reads from a VCF and
Section~\ref{sec:multipop} for what happens when a file holds more than one
population.  In that case each population is analysed separately, and the
output names carry the population label.

Two settings that earlier versions did not require are now needed.  A
chromosome that looks sex-linked is not analysed until {\tt --sex-system} says
what to do with it (Section~\ref{sec:sexchr}).  An assembly must also be
named, with {\tt --build}, a {\tt --centromere} file, or {\tt --no-centromere}
if the assembly has no gap to avoid.

\noindent If the automatic window size selection algorithm fails, you can
output the KDEs of the LOD score distribution for multiple window sizes
(without calling ROH) by using the {\tt --winsize-multi} argument, i.e.
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize-multi 30 40 50 60 70 80 90 --out example}
~\\\\
\noindent This will generate KDEs for your inspection.  Once you've chosen a
window size, you should rerun garlic specifying that size.  For example, if you
choose a window size of 60 SNPs, then you would run
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 60 --out example}
~\\\\
\noindent The automatic cutoff is the minimum of the window LOD score density, pooled over the cohort, between its two modes.  The non-autozygous mode is the tallest peak below zero and the autozygous mode is the tallest peak above zero ({\tt manual/lod-mode-rule.tex} gives the derivation).  A cohort without long runs still has a small mode above zero from short runs of background autozygosity, and gets a cutoff that calls only short runs (a simulated cohort whose chromosomes were built from independent 1-Mb blocks at an effective size of $200\,000$ was called at $1.2\%$ of the genome, in runs of at most 261\,kb).  A density with no peak above zero therefore means that the windows carry too little evidence, not that the cohort carries no autozygosity.  Examples are genotypes called from one or two reads under a population prior and a cohort of mixed depth pooled without {\tt --stratify-cutoff}.  Such a run completes with no calls and a warning, and {\tt .params.json} records the verdict with {\tt lod\_cutoff} null.  A density with no peak below zero stops and asks for {\tt --lod-cutoff}.  A cohort of a handful of individuals is still a case for a cutoff carried over from a comparable, larger cohort rather than for the automatic rule.

\noindent If you already know what LOD score cutoff to use (say you are
analyzing more individuals from a previously studied population), you can use
the {\tt --lod-cutoff} argument, i.e. if your LOD score cutoff is known to be
2.5 then you would run
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 60 --out example --lod-cutoff 2.5}
~\\\\
\noindent If you already know what size thresholds to use for size
classification (say you are analyzing more individuals from a previously
studied population), you can use the {\tt --size-bounds} argument, i.e. if your
size thresholds are known to be 500000 and 1000000 for the boundaries between
short/med and med/long, respectively, then you would run
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 60 --out example --lod-cutoff 2.5 --size-bounds 500000 1000000}
~\\\\
\noindent Supplying both is also how to reproduce an analysis made with an
earlier version, whose automatic cutoff selection differed.  The values to
pass are in that run's log.
~\\\\
\noindent To run the wLOD, you must provide a map file and give the
{\tt --weighted} flag:
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --map example.map.gz --weighted --build hg18 --winsize 60 --out example --error 0.001}
~\\\\
\noindent To count classified genotypes (deleterious against tolerated, for
example) inside and outside the calls, add {\tt --features} with a file
classifying the sites (Section~\ref{sec:features}):
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 60 --lod-cutoff 2.5 --size-bounds 500000 1000000 --features classes.txt --out example}
~\\\\
\noindent Other command line arguments are described below, and all of them are
listed with their types and defaults in Appendix~\ref{app:flags}.

\section{Statistics implemented}
\label{sec:lod}

We previously advocated the application of a logarithm of the odds (LOD) score measure of autozygosity applied in a sliding-window framework to infer ROH in high-density SNP genotype data \cite[]{PembertonEtAl12:AJHG}. Fundamentally, for SNP $k$ in individual $i$, this method calculates the log-likelihood ratio of observed genotype $G_{i,k}$ under the hypotheses of autozygosity and non-autozygosity, incorporating an assumed genotype error rate $\epsilon$ and population-specific allele frequencies. The LOD score of window $w$ in individual $i$ is then calculated as the sum of the log-likelihood ratios of the $K$ SNPs in the window: 
\begin{equation}
LOD(w,i)= \sum_{k=1}^K \log_{10}\Big(\frac{Pr[G_{i,k} | X_k = 1]}{Pr[G_{i,k} |X_k=0]}\Big).
\end{equation}
Here, $Pr[G_{i,k} |X_k=1]$ is the probability of observing genotype $G_{i,k}$ under the hypothesis of autozygosity ($X_k=1$), and $Pr[G_{i,k} |X_k=0]$ is the probability of observing genotype $G_{i,k}$ under the hypothesis of non-autozygosity ($X_k=0$). For a biallelic locus with alleles $A$ and $B$ that have population frequencies $p_A$ and $p_B$ and a genotype error rate $\epsilon$, the genotype probabilities under the autozygosity and non-autozygosity hypotheses are given in Table 1.

Calculating $LOD(w,i)$ for all windows in all individuals in a given sample set, examination of the distribution of scores shows clear bimodality, with windows in the left-hand mode supporting the hypothesis of non-autozygosity and those in the right-hand mode supporting the hypothesis of autozygosity. The area under the autozygous mode decreases with increasing window size until it disappears, potentially reflecting the window size beyond which window length is often longer than ROH length leading to the inclusion of non-autozygous regions in the $LOD(w,i)$ calculation that mask the presence of autozygosity. A logical window size to use for ROH detection is therefore the largest window size where the distribution of LOD(w,i) is bimodal, with windows defined as autozygous if their $LOD(w,i)$ is greater than the local minimum between the two modes. Contiguous autozygous windows are subsequently joined to define ROH.

If the weighted flag is used, wLOD scores will be calculated as
\begin{align}
wLOD(w,i) &= \sum_{k=1}^K \log_{10}\Big(\frac{Pr[G_{i,k} | X_k = 1]}{Pr[G_{i,k} |X_k=0]}\Big)\times Corr(p_k,[p_1,p_K]) \\ 
&\times Pr[norecombination|[g_{k-1},g_{k}]] \\ 
&\times Pr[nomutation|\mu,[p_{k-1},p_k]],
\end{align}
where
\begin{equation}
Corr(p_k,[p_1,p_K]) = \frac{1}{\sum_1^KLD_{k,i}},
\end{equation}
\begin{equation}
Pr[norecombination|[g_{k-1},g_{k}]] = e^{-2M(g_k-g_{k-1})},
\end{equation}
and
\begin{equation}
Pr[nomutation|\mu,[p_{k-1},p_k]] = e^{-2M\mu(p_k-p_{k-1})}.
\end{equation}
$LD_{k,i}$ is computed as $r^2$ if data are phased and as $HR^2$ if data are unphased. $g_i$ and $p_i$ are the genetic distance and physical distance at marker $i$, respectively.

\subsection{Input Files}

Genotypes are read from a VCF ({\tt --vcf}), a TPED/TFAM pair ({\tt --tped}/{\tt --tfam}, see \\{\tt http://pngu.mgh.harvard.edu/\textasciitilde purcell/plink/data.shtml\#tr}).  The two are mutually exclusive.  Either may be read gzipped ({\tt http://www.gzip.org/}) without decompressing first, and a VCF may also be BGZF, as written by {\tt bgzip} or {\tt bcftools}.  Loci are assumed to be in order of physical position, and all records for a chromosome must be contiguous, as {\tt bcftools sort} produces.  A locus may carry at most two alleles: a TPED line with three distinct alleles, or a VCF position on more than one record, stops the run with an error that names the site.  If the file contains more than one population, each is analysed separately (Section~\ref{sec:multipop}).  {\tt --pop} overrides the labels, which for a TPED/TFAM pair are otherwise taken from column 1 of the TFAM.

\subsubsection{VCF input}
\label{sec:vcf}

Biallelic SNVs carrying a {\tt GT} field are used.  Multiallelic sites, indels, symbolic ALT alleles ({\tt *}, {\tt <NON\_REF>}) and records with no {\tt GT} in {\tt FORMAT} are skipped, and the number of each is written to the log.  The {\tt FILTER} column is reported but acted on only under {\tt --vcf-pass-only}, since it records the variant caller's thresholds rather than {\tt garlic}'s.

A position on more than one record is an error.  Splitting multiallelic sites ({\tt bcftools norm -m-}) produces this, and {\tt garlic} would otherwise score each record as a separate SNP in the same window: a heterozygote carrying both ALT alleles would be counted twice when the other ALT is written as {\tt 0}, and not at all when it is written as {\tt .}, because each record then holds a half call.  Every record counts towards the check, indels and filtered records included, because the SNV left over from splitting {\tt A}$\to${\tt C,AT} is scored with the indel's carriers coded as REF or missing.  Rejoin split records with {\tt bcftools norm -m+any}.  {\tt garlic} then skips the multiallelic site and counts it in the log.

A VCF states things that a TPED cannot, and {\tt garlic} checks them.  Ploidy is given per call, so anything other than a diploid genotype is an error that names the site and the sample, except on a declared sex chromosome (Section~\ref{sec:sexchr}).  Phase is also given per call, so {\tt --phased} requires {\tt |} in every call.  Samples are named in the {\tt \#CHROM} line, so {\tt --tfam} is not accepted with {\tt --vcf}.  Use {\tt --pop} for population labels.  Without it every sample is labelled {\tt unknown} and {\tt garlic} warns, because the allele frequencies are then pooled over all samples.  With {\tt --pop}, each population is analysed separately (Section~\ref{sec:multipop}).

The counted allele is ALT.  For the same genotypes a TPED counts whichever allele it saw first, so the frequency column may come out as $1-f$ relative to a TPED run.  This changes no ROH call, and a {\tt .freq.gz} file can be used with either reader, because {\tt garlic} compares the file's {\tt ALLELE} column against its own coding and flips the frequency when they differ.

Genetic map positions are not part of a VCF, so {\tt --weighted} and {\tt --cm} still require {\tt --map}.

Per-genotype qualities are read from the {\tt FORMAT} column with {\tt --gl-type}.  This is the only correct way to use a VCF's {\tt PL} or {\tt GL}.  A VCF normalises both so that the called genotype's value is exactly $0$ for every call, confident or not, and the information is in how much worse the alternatives are.  {\tt garlic} therefore reads the whole array and computes
\[ P(g) \propto 10^{-\mathrm{PL}_g/10}, \qquad \mathrm{error} = 1 - \frac{P(\mathrm{called})}{\sum_g P(g)}, \]
with {\tt GL} entering the same expression as $\mathrm{PL} = -10\,\mathrm{GL}$.  This reproduces the {\tt GQ} that encodes the same confidence (a {\tt PL} of $(0,30,60)$ gives $0.001$, exactly {\tt GQ} $30$).  If the requested field is absent the run stops, and the message names whichever of {\tt GQ}, {\tt PL} and {\tt GL} the record does carry.

\paragraph{Low-coverage sequence data.}  None of the per-genotype quality forms above is suitable for low-coverage sequencing (below roughly $4\times$).  Each of them gives one error rate per genotype and is evaluated at the called genotype, so an uncertain homozygous call still counts as evidence for autozygosity, only with a smaller weight.  At low depth the dominant error is allelic dropout, in which the reads sample only one of a heterozygote's two alleles.  Dropout turns heterozygotes into homozygotes, and a run of such calls is what autozygosity looks like to the LOD score.  In a simulation of independent sites with reads drawn at $0.5$--$1\times$ (60-SNP windows, 10\% of the genome autozygous), a per-genotype error taken from {\tt GQ} called essentially the whole genome autozygous.  In the same simulation, hard calls made under a Hardy-Weinberg prior with a run-wide {\tt --error} degraded more gracefully but lost the automatic cutoff at $2\times$.

The companion script {\tt vcf2tped.pl} is deprecated.  It writes a TPED and a {\tt tgls} file, and a {\tt tgls} file holds one value per genotype, which cannot represent a normalised {\tt PL} or {\tt GL}.  {\tt garlic} rejects such a file.
\subsubsection{Cohorts of mixed depth: {\tt --stratify-cutoff}}
\label{sec:stratify}

The automatic LOD score cutoff is the valley between the two modes of the window LOD density pooled over every individual.  This is appropriate when every individual carries the same evidence per window.  However, an individual at low depth, or with many missing genotypes, has both of its modes compressed toward zero, so a cutoff placed for the cohort calls most of its genome autozygous.

The location of an individual's non-autozygous LOD mode is a precise measure of the evidence its windows carry.  On the bundled cohort it varies by $1.3$ LOD between individuals.  {\tt --stratify-cutoff} sorts the individuals by that mode, joins neighbours whose modes differ by less than a quarter of the smaller spread into a stratum, and applies the pooled rule within each stratum.  A cohort of uniform evidence is one stratum and gets exactly the pooled cutoff (the test suite checks that the calls are byte-identical).  A mixed cohort splits by depth, and each stratum's valley rests on tens of thousands of windows rather than on one individual's.

The per-individual mode, spread, stratum and applied cutoff are written to {\tt <out>.ind.tsv}.  The {\tt .kde} file is the largest stratum's density, and {\tt .params.json} records {\tt lod\_cutoff} as the number of strata and flags it as such.  A stratum of fewer than three individuals does not get a valley of its own and takes the largest stratum's cutoff, with a warning.  One or two individuals' windows are too few for the rule, and such a stratum is as likely to be an individual whose lowest substantial mode is its autozygous one (more than half autozygous on the analysed chromosomes, as is one of the 45 individuals on chromosome 21 of the bundled data).  A stratum whose density has no valley borrows the median standardised valley of the other strata, through its own mode and spread.  The flag needs the automatic cutoff and does not subsample.

Without the flag, {\tt garlic} still locates the modes and warns when the cohort would form more than one stratum.  The warning names the strata, so a mixed cohort analysed with one cutoff is a visible choice.

\subsubsection{Reference and mapping bias: {\tt --exclude-regions}}
\label{sec:refbias}

Reads carrying the non-reference allele map less often and with lower quality, so at a true heterozygote the fraction of ALT reads is below one half.  In this model that is a {\em directional} error (a heterozygote observed as a reference homozygote), and a run of such calls is what autozygosity looks like.  The bias has two parts, and they are handled differently.

\paragraph{Regional bias} (repeats, segmental duplications, structurally divergent segments) mis-maps reads wholesale, and no per-site model recovers from it.  {\tt --exclude-regions <bed>} drops every site inside the regions of a BED file before anything is computed.  The file may be a mappability mask, a repeat annotation, segmental duplications, or any set of regions in which calls are not to be trusted.  It is standard BED (0-based half-open, further columns ignored, {\tt track}, {\tt browser} and {\tt \#} lines skipped), gzipped or not.  The mask applies on every chromosome, autosomes included.  Chromosomes in the file that are not in the data are ignored, since a genome-wide mask names them all.  A file that covers no site at all draws a warning, since that usually means the wrong assembly or chromosome naming.  The dropped sites are removed from the frequency file and from every window.  The $F_{ROH}$ denominator is not reduced by them, unlike with {\tt --par}, because a run of homozygosity can span a short masked region.  {\tt --freq-only} does not apply the mask and refuses the combination.

\paragraph{Read-level bias}, an ALT read fraction below one half at heterozygotes everywhere, is not corrected by {\tt garlic}.  It is best reduced before the data reach {\tt garlic}.
\begin{itemize}
\item Map to a reference that carries the alternative alleles (an alt-aware or pangenome mapper, or a population-matched reference).
\item Use ANGSD's {\tt -baq 1 -C 50} to down-weight mis-aligned bases, and its {\tt -minMapQ} and {\tt -minQ} filters.
\item Filter short reads, whose mapping is the most reference-biased.
\item For ancient DNA, rescale damaged bases ({\tt mapDamage}) or drop transitions ({\tt -rmTrans 1}), which also removes the deamination signal that mimics heterozygosity.
\item Take allele frequencies from a source that is not itself biased (ANGSD's {\tt -doMaf}, or {\tt --freq-file} from the high-coverage members of the cohort).
\end{itemize}

\subsubsection{File formats}
\noindent tped/tfam (required):\\
\begin{verbatim}
	http://zzz.bwh.harvard.edu/plink/data.shtml#tr
\end{verbatim}
\noindent map (required when {\tt --weighted} or {\tt --cm} are set):
\begin{verbatim}
	<chr> <snpid> <genetic pos> <physical pos>
	http://zzz.bwh.harvard.edu/plink/data.shtml#map 
	(negative positions will cause errors)
\end{verbatim}
\noindent tgls (optional and legacy, see the note on {\tt vcf2tped.pl} above):
\begin{verbatim}
	<chr> <snpid> <unused> <physical pos> <GL ind1> <GL ind2> ... <GL indN>
\end{verbatim}
\noindent One value per genotype.  Under {\tt --gl-type PL} or {\tt GL} these are read as the probability that the genotype is {\em correct}, which is not what a VCF's {\tt PL} and {\tt GL} fields hold, and a file of VCF-derived values is rejected with an error.  {\tt --gl-type GQ} is the one form whose VCF values can be used here directly.

\noindent exclude-regions (optional; see \S\ref{sec:refbias}):
\begin{verbatim}
	<chrom> <chromStart> <chromEnd> [ignored ...]
\end{verbatim}
\noindent Standard BED, 0-based half-open.  {\tt track}, {\tt browser} and {\tt \#} lines are skipped.

\noindent pop (optional, and with {\tt --vcf} the only way to set population labels):
\begin{verbatim}
	<sample id> <population> [sex]
\end{verbatim}
\noindent Matched by sample ID, never by position.  Note that the column order is the opposite of a TFAM's first two columns, and a TFAM-ordered file is diagnosed as such.  The optional third column uses PLINK sex coding.  On a declared sex chromosome a recorded sex is checked against the heterozygosity {\tt garlic} measures there, and the run stops if more than half the individuals contradict it (Section~\ref{sec:sexchr}).

\noindent freq (optional; written by every run, or on its own with {\tt --freq-only}):
\begin{verbatim}
	CHR SNP POS ALLELE FREQ
	<chr> <locus ID> <pos> <allele> <freq>
\end{verbatim}
\noindent With more than one population there is one frequency column per
population, headed by its label, in place of the single {\tt FREQ} column.  A
file carrying just one such column is applied to every population, whatever
that column is called (Section~\ref{sec:multipop}).

\noindent centromere file (one of {\tt --build}, this file, or {\tt --no-centromere} is required):
\begin{verbatim}
	<chr> <centromere start> <centromere end>
\end{verbatim}

\subsubsection{{\tt --tped}}

Use {\tt --tped <string>} to specify a .tped (transposed PLINK; \cite{PurcellEtAl07}) file (see \\{\tt http://zzz.bwh.harvard.edu/plink/data.shtml\#tr} for exact specifications) containing genetic variant information.  A locus with more than two distinct alleles, not counting the missing-data code, is an error.  {\tt garlic} counts one allele against the rest, so a third would be merged with the second and some heterozygotes scored as homozygotes.

\subsubsection{{\tt --tped-missing}}

Use {\tt --tped-missing <char>} to specify the missing data code in the .tped file.  Default is {\tt 0}.  


\subsubsection{{\tt --tfam}}

Use {\tt --tfam <string>} to specify a .tfam (transposed PLINK; \cite{PurcellEtAl07}) file (see \\{\tt http://zzz.bwh.harvard.edu/plink/data.shtml\#tr} for exact specifications) containing sample information.

\subsubsection{{\tt --tgls}}

Use {\tt --tgls <string>} A tgls file containing per-genotype likelihoods. Formatted: <chr> <snpid> <unused> <physical pos> <GL ind1> <GL ind2> ... <GL indN>. Default: none.

Per-genotype likelihoods should be given as either a phred-scaled ({\tt --gl-type PL}) or a $\log_{10}$-scaled ({\tt --gl-type GL}) representing the probability that the genotype is correct or a phred-scaled likelihood that the genotype is wrong ({\tt --gl-type GQ}).  For example, if $p = 0.999$ is the probability that the genotype is correct, then $PL = -10\log_{10}(p) = 0.00434511774018$, $GL = \log_{10}(p) = -0.000434511774018$, and $GQ = -10\log_{10}(1-p) = 30$.

\subsubsection{{\tt --centromere}}

Use {\tt --centromere <string>} to specify a file containing custom centromere boundaries formatted as
\begin{lstlisting}
<chr> <start> <end>
\end{lstlisting}

\subsubsection{{\tt --freq-file}}

{\tt --freq-file <string>} A file specifying allele frequencies for all variants. File format:
\begin{lstlisting}
CHR	SNP	POS	ALLELE	FREQ 
<chr>	<locus ID>	<pos>	<allele>	<freq>
\end{lstlisting}
~\\
\noindent By default, this is calculated automatically from the provided data.

\subsubsection{{\tt --map}}

{\tt --map <string>} gives a scaffold genetic map.  Sites that are not in the file are interpolated, and sites outside its bounds are filtered.  The map is required for wLOD calculations and for reporting ROH in units of cM.  Its format is given under File formats above, and negative positions cause errors.

\subsection{Output Files}

{\tt garlic} produces several files as output.  The {\tt .log} file records
the runtime parameters, and {\tt .error} records any errors that occur.
{\tt .error} is created only if something is written to it.  A
{\tt .params.json} file records the effective value of every flag together
with the values resolved during the run (selected window size, LOD cutoff, size
class boundaries and random seed), and it can be replayed with
{\tt --load-params}.

A gzipped {\tt .freq} file will be output giving the allele frequencies for each locus in the dataset.  Formatted as
\begin{lstlisting}
CHR	SNP	POS	ALLELE	FREQ
<chr>	<locus ID>	<pos>	<allele>	<freq>
\end{lstlisting}
~\\
With more than one population the file carries one frequency column per population, headed by its label:
\begin{lstlisting}
CHR	SNP	POS	ALLELE	POPA	POPB
<chr>	<locus ID>	<pos>	<allele>	<freq>	<freq>
\end{lstlisting}
~\\
This is the format {\tt --freq-file} reads, so a run's own frequency file can be given back to {\tt garlic} to reproduce that run.  A file with a single frequency column is applied to every population, whatever the column is called, so a frequency file from an earlier version can still be used.  {\tt --freq-only} writes the same file without performing the analysis.
~\\
With {\tt --froh}, a {\tt .froh.tsv} table gives each individual's autozygous
total and the fraction of the genome it covers, one row per individual with the
size classes across the columns.  The denominator is stated in the header, as
are the size-class boundaries actually used, so the fractions can be recomputed
or compared across runs.

{\tt --froh-denominator} chooses what that fraction is taken of.
{\tt analyzed}, the default and what {\tt garlic} has always done, is the span
the markers cover, from the first to the last locus of each analysed
chromosome, less the centromere and any region excluded with {\tt --par}.  This
is what a marker set can support on its own, but it moves with the marker set,
so F$_{\mathrm{ROH}}$ values from two different arrays are not directly
comparable.  {\tt assembly} is the full length of each analysed chromosome,
with nothing subtracted (not the centromere, the pseudoautosomal regions or the
part beyond the outermost marker).  Published F$_{\mathrm{ROH}}$ denominators
are of this kind.  For example, the hg19 autosomes sum to
2,881,033,286\,bp and chrX is 155,270,560\,bp, which are the 2881.03\,Mb and
155.27\,Mb of \citet{CotterEtAl24}.  On the bundled example data the two
denominators differ by about 5\%.

The sum is over the chromosomes that were {\em analysed}, and the assembly
supplies each one's length.  A run restricted with {\tt --chr} is divided by
those chromosomes alone, and a contig that carries no data is never looked up,
so a VCF full of decoys, unplaced scaffolds and alternate haplotypes needs no
filtering here.  A chromosome that was analysed and has no length available
stops the run rather than falling back to its marker span, since mixing the
two conventions across chromosomes gives a denominator that is neither.

Lengths come from {\tt --chr-lengths}, from {\tt --build}, or from a VCF's
{\tt \#\#contig} header, in that order of precedence.  {\tt --chr-lengths} takes
two whitespace-separated columns, chromosome and length, and also accepts a
{\tt samtools faidx} {\tt .fai} unchanged, since its first two columns are
already name and length.  It is the way to use this mode on a non-human
assembly and on TPED input, where nothing in the data states a length.  The
built-in tables are the GRC assembly reports' own numbers, recorded with their
source in {\tt centromeres/chr\_lengths.txt}.  {\tt assembly} is refused with
{\tt --cm}, because a chromosome's length in base pairs is not its length in
centimorgans.

Whenever lengths are available, {\tt garlic} checks that no marker lies beyond
the end of its chromosome.  This is how a wrong {\tt --build} shows itself, and
nothing else in the program can detect it.  The check matters in either mode,
because the centromere and pseudoautosomal coordinates in use came from the
same assembly.  Under {\tt assembly} a violation stops the run, since those
lengths are the denominator.  Under {\tt analyzed} they feed nothing, so it is
a warning.  Where a VCF header and {\tt --build} both state a length and
disagree, one of them is not this assembly, and {\tt garlic} reports the
conflict rather than choosing one.

Kernel density estimation of the LOD score distribution is output to {\tt .<winsize>SNPs.kde} formatted as
\begin{lstlisting}
<LOD score> <density>
\end{lstlisting}
~\\
ROH calls are output to {\tt .roh.bed}, which are formatted as UCSC BED files. There is one track per individual (all individuals in the same file) and the data are formatted as
\begin{lstlisting}
<chr> <ROH start> <ROH end> <size class> <ROH length> <placeholder> <placeholder> <placeholder> <RGB track color>
\end{lstlisting}
~\\
\noindent Following the BED specification, {\tt <ROH start>} is 0-based and
{\tt <ROH end>} is exclusive, so {\tt <ROH end>} minus {\tt <ROH start>}
equals {\tt <ROH length>}.  Note that under {\tt --cm} the boundaries remain
physical positions while {\tt <ROH length>} is reported in cM, so the identity
does not hold in that mode.  Versions before 2.0.0 wrote {\tt <ROH start>} as
a 1-based position, so coordinates from those versions are shifted by one
relative to these.
~\\
When requested, raw LOD scores are also output.  This file contains one row per individual (corresponding to the order in the {\tt .tfam} file), and LOD scores for each window are given on the columns.
\begin{lstlisting}
<LOD score window 1> <LOD score window 2> ... <LOD score window N>
\end{lstlisting}
~\\

\paragraph{The per-individual information report.}\label{sec:ind}  Every run also writes {\tt <out>.ind.tsv} (per population when there are several), with one row per individual.  A window's LOD is a sum over the sites in it, and a site that carries no information for an individual (a missing genotype) contributes exactly 0.  Two individuals with the same window size can therefore be summing very different amounts of evidence.  The report records, per individual:
\begin{itemize}
\item {\tt n\_sites}, the analysed sites on chromosomes where the individual is diploid;
\item {\tt frac\_informative}, the fraction of them with a called genotype;
\item {\tt snps\_per\_window\_median} and {\tt \_p05}, the median and 5th percentile of informative sites per window;
\item {\tt n\_het\_expected}, the sum of $2p(1-p)$ over the sites used for {\tt het\_obs\_exp};
\item {\tt het\_obs\_exp}, observed over expected heterozygotes from called genotypes.
\end{itemize}
\noindent The last two are computed over the sites in windows whose LOD is below 0, which stand in for non-autozygous windows without needing the cutoff, so they are not confounded by the individual's own autozygosity.  {\tt garlic} warns when an individual's 5th percentile falls below half the window size.

{\tt het\_obs\_exp} is the ordinary sample-quality statistic for called data, and it is not a low-depth estimator.  At low depth it reads well below 1 even without any bias, because the maximum-likelihood call at one or two reads is a homozygote.  Its sampling noise is roughly $1/\sqrt{\tt n\_het\_expected}$, a few hundredths on one chromosome and a few thousandths genome-wide, so it should be read against the cohort rather than as an absolute.  It corrects nothing, and the report is there so that an individual whose data differ from the rest of the cohort can be seen.

\subsubsection{{\tt --out}}

Use {\tt --out <string>} to provide a base name for an output file.  This will be used in place of {\tt <outfile>} above.  Default value is {\tt outfile}.  

\subsection{Multiple populations}
\label{sec:multipop}

The LOD score is parameterised by population allele frequency, so pooling
distinct populations inflates heterozygosity relative to any one of them and
biases the ratio for all of them.  When the input contains more than one
population label, {\tt garlic} therefore analyses each population separately
and in turn.  Each receives

\begin{itemize}
\item allele frequencies computed from its own individuals;
\item its own site filtering, so a site that is monomorphic in one population
      but polymorphic in another is dropped where it is uninformative;
\item its own automatically selected window size, LOD score cutoff and
      size-class boundaries;
\item its own random number stream, derived from {\tt --seed}, so its result
      does not depend on how many populations preceded it in the file.
\end{itemize}

\noindent A value given explicitly on the command line is not re-derived, so
{\tt --winsize}, {\tt --overlap-frac}, {\tt --lod-cutoff} and
{\tt --size-bounds} apply to every population.

Analysing several populations together therefore gives each of them exactly
what analysing it alone would give.  The populations do not interact, so
running them in one command is only a convenience.

Populations are processed one at a time, so peak memory is bounded by the
largest population rather than by their sum.

\subsubsection{Where the labels come from}

For a TPED/TFAM pair the label is column 1 of the TFAM.  PLINK calls that
column the family ID, and in many files it holds one family, or even one
sample, per value.  Such a file produces one analysis per family, which is
almost certainly not what was intended.  {\tt garlic} warns when the smallest
population has fewer than five individuals, and again when there are fewer
than two individuals per population on average, but it cannot tell the two
situations apart with certainty.  Use {\tt --pop} to supply real population
labels, or {\tt --pool-populations} to ignore them.

A VCF carries no population labels, so {\tt --pop} is the only way to set them;
without it every sample is labelled {\tt unknown} and the analysis is pooled.

\subsubsection{Output files}

With one population the output file names are unchanged.  With more than one,
the population label is inserted before the extension:
{\tt <out>.<POP>.roh.bed}, {\tt <out>.<POP>.froh.tsv}, {\tt <out>.<POP>.ind.tsv},
{\tt <out>.<POP>.params.json} and {\tt <out>.<POP>.<winsize>SNPs.kde}.  The
{\tt .log}, {\tt .error} and {\tt .freq.gz} files are written once for the
whole run.

\subsubsection{{\tt --pool-populations}}

This flag makes {\tt garlic} ignore the labels and analyse every individual
together, as it did before per-population analysis.  Allele frequencies, the
LOD score cutoff, the window size and the size classes are then computed over
every sample at once, and the unlabelled output names are restored.  Use it
when the labels are not populations, or to reproduce a run from an earlier
version.  The {\tt .froh.tsv} header and {\tt .params.json} both record that
the populations were pooled.

\subsubsection{When a population cannot be analysed}

A small population can fail size-class fitting or cutoff selection where a
pooled fit would have succeeded.  {\tt garlic} reports which population failed
and stops, rather than writing a partial set of results that looks complete.
Supplying {\tt --size-bounds} or {\tt --lod-cutoff} avoids the automatic step
that failed.

\subsection{Sex chromosomes}
\label{sec:sexchr}

A hemizygous genotype is written as a homozygous call, so a sex chromosome
analysed as an autosome is called as one run spanning its whole length in
every heterogametic individual, and any $F_{ROH}$ computed from that is
inflated.  {\tt garlic} therefore refuses to analyse a chromosome that looks
sex-linked until it is told what to do with it.

\subsubsection{Declaring the system}

{\tt --sex-system} takes {\tt xy}, {\tt zw} or {\tt none}.  It supplies the one
thing that genotype data cannot, which is the sex \emph{code} that is
heterogametic.  PLINK codes 1 male and 2 female whatever the species' sex
determination system is, so in a ZW species the \emph{homogametic} sex is the
one coded 1.  Leaving the flag unset is not the same as {\tt none}, because
unset means nothing has been said and the run stops, while {\tt none} asserts
that every chromosome is diploid in every individual.

The conventional names follow from the system (X and Y under {\tt xy}, Z and
W under {\tt zw}, plus M or MT for the mitochondrion).  A chromosome with any
other name is declared explicitly with {\tt --sex-chr} (diploid in the
homogametic sex), {\tt --sex-chr-degenerate} (carried only by the heterogametic
sex) or {\tt --haploid-chr}.  A chromosome's role does not depend on the
system, so X and Z are both the shared chromosome and Y and W are both the
degenerate one.  Only the shared chromosome is analysed.  The others cannot
carry a run of homozygosity in anybody, and they are dropped with a log line.

The numbers 23, 24, 25 and 26 are X, Y, the pseudoautosomal region and the
mitochondrion under PLINK's coding of \emph{human} data, and ordinary autosomes
in any species with that many chromosomes.  {\tt garlic} resolves them only
when {\tt --build} names a human assembly, since that already asserts human
coordinates.  Without one it refuses rather than picking a reading.

\subsubsection{What the analysis does}

Allele frequencies on the shared sex chromosome are computed over
\emph{everyone}, with the heterogametic sex contributing one allele and the
homogametic sex two.  Runs of homozygosity are then called only in the
individuals who are diploid there.  The LOD score cutoff, the window size and
the size-class boundaries are estimated on the autosomes and applied to the sex
chromosome, and {\tt garlic} reports what the sex chromosome's own windows
would have given.  This follows \citet{CotterEtAl24}, who give the reason for
the cutoff: one chromosome's windows from part of a cohort usually cannot
locate a second minimum in the density.

This is the default rather than the only option.  When the reported diagnostic
shows that the autosomal cutoff is badly placed on the sex chromosome, another
cutoff can be given with {\tt --sexchr-lod-cutoff}, and a different window
size with {\tt --sexchr-winsize}.  Both apply to the shared sex chromosome
alone and leave every autosomal call where it was.  Because the estimate on
that chromosome usually fails, these flags take values rather than asking
{\tt garlic} to re-estimate, and the diagnostic is where the values come from.
A LOD score cutoff is specific to the window size it was estimated at, so
{\tt --sexchr-winsize} requires {\tt --sexchr-lod-cutoff}.  The values that
were applied, whether or not the flags were given, are recorded in
{\tt <out>.params.json} as {\tt sexchr\_winsize} and {\tt sexchr\_lod\_cutoff}.

A half call carries no genotype.  The LOD score takes its default branch for
one, so {\tt --tgls} and a VCF's {\tt GQ}, {\tt PL} or {\tt GL} need no special
handling, since the per-genotype error rate is never read there.  This matters
for a hemizygous VCF, where a haploid {\tt PL} array holds one value per allele
(two at a biallelic site rather than three), because the array is never
parsed.  Both LD statistics behind {\tt --weighted} also skip an uncalled
genotype, so the LD matrix on the shared sex chromosome is estimated among the
individuals who are diploid there.  Under {\tt --ld-subsample} the subsample
for that chromosome is drawn from those individuals, so the number requested is
the number that informs it.

Who is diploid there is established by a check that always runs.  Each
individual's heterozygosity on that chromosome is compared against
{\tt --het-rate-bounds} (0.02 and 0.10 by default).  Below the first bound the
individual reads as hemizygous, above the second as diploid, and between them
as ambiguous, in which case it is neither called there nor counted towards the
allele frequency.  A recorded sex is checked against this, and an unrecorded
one is inferred from it.  The per-individual result is written to
{\tt <out>.sexcheck.tsv}.  Heterozygous calls in an individual with one copy of
the chromosome are impossible, so they are counted and discarded.  If more
than half the individuals with a recorded sex contradict it, {\tt garlic}
stops, because either {\tt --sex-system} is inverted or the chromosome was
called as diploid, and continuing would discard every one of those calls.

$F_{ROH}$ is reported separately for the autosomes and for the sex chromosome,
each with its own denominator, and is {\tt NA} rather than zero for an
individual that cannot be autozygous there.  The two are not summed.  The X
coalesces faster than the autosomes and carries more homozygosity at the same
level of consanguinity, so the two quantities should be compared rather than
pooled.

\subsubsection{Pseudoautosomal regions}

A pseudoautosomal region is diploid in both sexes.  {\tt --par} takes one or
more {\tt <chr>:<start>-<end>} intervals, and {\tt --par-file} reads them from
a file.  Both accept any number of regions per chromosome (humans have two),
and the two flags accumulate.  Unlike {\tt --centromere}, repeated rows for one
chromosome add a region rather than replacing one.  The loci inside are
dropped, each region's count is reported separately, and a region that matches
no locus draws a warning that names it.

They are identified by coordinates on a declared sex chromosome and never by a
chromosome code, because PLINK's 25 is an ordinary autosome in most species.

For the human X, {\tt --build} supplies the regions.  The coordinates are the
Genome Reference Consortium's own definition for that assembly, recorded with
their source in {\tt centromeres/par\_regions.txt}, and they are filed under
whatever name the data gives that chromosome ({\tt chrX} in one file and
{\tt 23} in the next).  Naming any region with {\tt --par} replaces them, and
{\tt --par none} turns them off.  No table is supplied for any other shared sex
chromosome.

Running without the regions, on a non-human assembly or under {\tt --par none},
has a bounded cost.  The heterogametic sex's genotypes in a pseudoautosomal
region are recoded as hemizygous along with the rest of the chromosome.  Their
real heterozygous calls there are therefore counted as impossible and
discarded, which inflates {\tt n\_het\_recoded} by roughly that region's share
of the markers (about 1--2\% of the human X).  Their contribution to the allele
frequency in the region is also biased, because dropping heterozygotes while
keeping homozygotes is not a random thinning.  Both effects are bounded by the
total pseudoautosomal share of the chromosome, which is larger in a species
that has several such regions.

\subsubsection{Chromosome names}

Names are matched case-insensitively and ignoring a leading {\tt chr}, so
{\tt chrX}, {\tt chrx}, {\tt CHRX}, {\tt X} and {\tt x} are one chromosome, and
so are {\tt 1}, {\tt 01} and {\tt chr1}.  Output keeps whatever the input said.
Two chromosomes in one file whose names differ only in this way are an error.
So is the same name appearing twice, which means that one chromosome's rows are
not contiguous.  {\tt garlic} starts a new chromosome whenever the chromosome
column changes and would otherwise analyse it as two.

\subsection{Counting classified genotypes}
\label{sec:features}

\noindent A common use of a set of runs of homozygosity is to ask whether
genotypes of some class (deleterious, non-synonymous, or whatever an annotation
supplies) are found inside them more often than outside.  {\tt --features}
does that counting as part of the run that makes the calls, and writes
{\tt <out>.counts.tsv}.

The classification is a file of four whitespace-separated columns, the
chromosome, the position, the allele that carries the classification, and the
class label:

\begin{lstlisting}
#chr   pos        allele  class
chr21  15481365   T       probably_damaging
chr21  15481365   T       nonsynonymous
21     15502312   A       benign
\end{lstlisting}

\noindent The label is arbitrary text, and there may be any number of distinct
labels.  A site may appear more than once, as the first two rows above do, so
two annotation schemes can classify the same variant, and the categories need
not be mutually exclusive.  The same class twice at one site is an error.
Chromosome names are matched ignoring case and a {\tt chr} prefix, and the
allele is compared as a string, so an indel allele from a sequenced call set
works as well as a single base.

For every individual and every class, the table gives three numbers in each
bucket.  {\tt hom} is the number of genotypes homozygous for the classified
allele, {\tt het} the number carrying one copy, and {\tt n} the number of
classified sites at which that individual has a genotype at all.  The last is
the denominator, and it separates ``more deleterious homozygotes inside runs''
from ``more sites inside runs''.  The buckets are the size classes the
population was analysed with, then {\tt NONE}, then {\tt UNASSESSED}, then
{\tt ALL}.  The count inside runs of homozygosity is {\tt ALL} less
{\tt NONE} less {\tt UNASSESSED}.

{\tt UNASSESSED} counts sites where no run could have been called for anybody:
a chromosome that was not analysed, one carrying fewer than two loci, an
assembly gap, a region excluded by {\tt --par}, or a position outside the span
the markers cover.  It is kept apart from {\tt NONE} because folding the two
together inflates the outside-runs count by however much of the genome the
analysis left out.  Two further columns account for the rest of each
individual's classified sites.  {\tt n\_hemi} counts sites on a chromosome
where that individual is not diploid, and {\tt n\_missing} counts sites it has
no call for.  Every classified row lands in exactly one of these places, so
$\sum {\tt ALL\_n} + {\tt n\_missing} + {\tt n\_hemi}$ is the same for every
individual the genotypes covered.

The genotypes are read from the file without filtering.  The filtered matrix
that {\tt garlic} calls from has had monomorphic sites dropped population by
population, has been pruned by {\tt --chr} and {\tt --autosomes-only}, and has
had excluded regions removed, and counting from it would discard exactly the
rare functional sites the question is about.  By default the input the run was
called from is read a second time.  When the classified variants are in
another file (calls from a genotyping array and classifications from
sequencing, for example), give that file with {\tt --tped-counting} and
{\tt --tfam-counting}, or with {\tt --vcf-counting}.  The two files need not
share a single site.  Individuals are matched by identifier, and one present in
only one of the two files is reported rather than counted as having no runs.

\subsubsection{Counting against calls that already exist}

\noindent {\tt --roh-file} counts against a {\tt .roh.bed} written earlier, or
published, instead of calling anything. It needs {\tt --features} and one of
the counting genotype flags, and it accepts no calling input.

Less can be known this way, and the table records it.  A {\tt .roh.bed}
records where the runs are, but not which chromosomes were analysed, how far
the markers reached, or what the size class letters mean.  So nothing can be
marked {\tt UNASSESSED}, every site outside a run is {\tt NONE}, and the size
class boundaries are reported as unknown.  Counting inside the run that makes
the calls knows all three, so it is preferable where there is a choice.

Note that version 1.1.6a was released with two different {\tt chromStart}
conventions under the same version string, so the version in a file's track
line does not say which one it uses.  {\tt garlic} works it out from the file
instead.  A conforming BED has ${\tt chromEnd} - {\tt chromStart}$ equal to the
length column, and the older convention has it one less.  The convention is
determined from every call rather than from the first, a file that is half
each is refused as two files concatenated, and the convention used is recorded
in the output header.  Under {\tt --cm} the length column is a genetic distance
and settles nothing, so that case draws a warning that names its
assumption.

--stratify-cutoff chooses the automatic LOD cutoff within strata of individuals that carry
the same evidence per window (grouped by the location of their non-autozygous LOD mode), so a
cohort of mixed depth is not over-called in its shallow members. A uniform cohort gets the
pooled cutoff exactly. Without the flag, garlic warns when the cohort would form more than
one stratum. See "Cohorts of mixed depth" under Input Files.

--exclude-regions <bed> drops the sites inside a mappability or repeat mask before anything is
computed, on every chromosome. This corrects the regional part of mapping bias, and it is the
only correction for mapping bias that garlic applies. See "Reference and mapping bias" under
Input Files.

A locus with more than two alleles is an error from either reader. A TPED line with three
distinct alleles was read as the first allele against the rest, so some heterozygotes were
scored as homozygotes. A VCF position on several records, which is how bcftools norm -m-
writes split multiallelic sites, was read as that many separate SNPs. Every record counts
towards a repeated position, indels and filtered records included. bcftools norm -m+any
rejoins the records, and garlic then skips the multiallelic site as before. --freq-only
applies the same rules. See "VCF input" under Input Files.
