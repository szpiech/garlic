\section{Introduction}

Extended tracts of homozygosity in individual genomes manifest as a result of haplotypes inherited identical by descent (IBD) from both biological parents. These runs of homozygosity (ROH) are important genomic features, with their length distributions and genomic locations informative about population history and useful for the mapping of recessive loci contributing to Mendelian and complex diseases. However, precisely because the length distribution of ROH is affected by population history, a simple one-size-fits-all genotype-counting approach to inferring ROH in multiple populations is ill-advised. Here, we present a model-based method and accompanying software package for inferring ROH in microarray-derived SNP genotype that incorporates population-specific parameters and genotyping error rates as described in \cite{PembertonEtAl12:AJHG}. Version 1.1.0 added a method for reweighting LOD scores by gaps between SNPs, the option to report ROH lengths in cM, and the ability to provide per-genotype error rates.  Version 2.0.0 reads VCF input directly (Section~\ref{sec:vcf}), analyses each population in a file separately rather than pooling them (Section~\ref{sec:multipop}), calls runs on the shared sex chromosome instead of treating it as an autosome (Section~\ref{sec:sexchr}), and counts classified genotypes inside and outside the calls (Section~\ref{sec:features}).  It is not backward compatible with files written by v1.1.6a; the change log in Section~\ref{sec:changelog} says how.

If you use GARLIC please cite the following articles,

\noindent ZA Szpiech, A Blant, TJ Pemberton. (2017) GARLIC: Genomic Autozygosity Regions Likelihood-based Inference and Classification. Bioinformatics doi: 10.1093/bioinformatics/btx102.
\\\\
TJ Pemberton, et al. (2012) Genomic patterns of homozygosity in worldwide human populations. American Journal of Human Genetics, 91, $275-292$.

\section{Obtaining {\tt GARLIC}}

{\bf NOTE TO WINDOWS USERS: {\tt ann\_figtree\_version.dll} and {\tt figtree.dll} are no longer needed.}  Earlier versions required both alongside {\tt garlic.exe}; {\tt GARLIC} no longer links FIGTree or ANN, so a copy of {\tt garlic.exe} built from this version runs without them.

{\tt GARLIC} pre-built binaries and source code are available at {\tt https://github.com/szpiech/garlic}.  To compile from source, change directories to the {\tt src/} directory and type {\tt make}; the Makefile detects the platform from {\tt uname}, so no editing is needed.  {\tt GARLIC}'s only external dependency is the zlib library ({\tt http://www.zlib.net/}), provided by the system on Linux and macOS, where the Makefile simply links {\tt -lz}.  Threading uses {\tt std::thread} from the C++11 standard library rather than calling pthreads directly; libstdc++ implements it over pthreads on Linux, so {\tt -pthread} is still passed there, but no pthreads library is named or vendored on any platform.  GNU GSL and FIGTree were required by earlier versions and are no longer used: FIGTree was replaced by a direct Gaussian sum, and GSL by {\tt src/garlic-math.cpp}, which reproduces the routines {\tt GARLIC} used bit for bit.  On Windows, zlib likewise comes from the MinGW toolchain ({\tt mingw-w64-x86\_64-zlib} under MSYS2's MINGW64); the 32-bit zlib that earlier versions vendored under {\tt lib/win32} has been removed, since a 64-bit MinGW cannot link it.  The windows version of {\tt GARLIC} is built in an MSYS2/MinGW environment ({\tt https://www.msys2.org/}); since the move to {\tt std::thread} it requires a MinGW GCC configured with the POSIX threading model, which is what provides {\tt std::thread} on that platform.

\section{Basic Usage}

A run needs genotypes, an assembly, a genotyping error rate and a name for the
output.  The bundled example is human SNP-array data on hg18 coordinates:
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 30 --auto-winsize --out example}
~\\\\
\noindent A priori we do not know how large to make the window, so this uses
the built-in search ({\tt --auto-winsize}).  The search begins at the
{\tt --winsize} value and increases, so a starting size is required --- giving
{\tt --auto-winsize} alone is an error rather than a default.  All output is
named starting with {\tt example} ({\tt --out example}), and on this data the
search settles on 50 SNPs, producing:

\begin{itemize}
\item {\tt example.log} --- the run's parameters and progress;
\item {\tt example.params.json} --- every flag's effective value together with
      the window size, LOD cutoff, size-class boundaries and random seed the
      run resolved, replayable with {\tt --load-params};
\item {\tt example.freq.gz} --- the allele frequencies used;
\item {\tt example.50SNPs.kde} --- the LOD score density at the selected window
      size, which is part of the file name;
\item {\tt example.roh.bed} --- the calls.
\end{itemize}

\noindent An {\tt example.error} file appears beside these only if something is
actually written to it.  Adding {\tt --froh} writes {\tt example.froh.tsv}, one
row per individual giving the autozygous total and the fraction of the genome
it covers.

The same run from a VCF needs no {\tt --tfam}, since a VCF names its samples,
but it does need {\tt --pop} if the samples are not all one population:
~\\\\
{\tt garlic --vcf cohort.vcf.gz --pop cohort.pop --build hg38 --error 0.001 --winsize 30 --auto-winsize --out cohort}
~\\\\
\noindent Both readers accept gzipped input directly, and a VCF may also be
BGZF.  See Section~\ref{sec:vcf} for what {\tt garlic} reads from a VCF and
Section~\ref{sec:multipop} for what happens when a file holds more than one
population --- each is analysed separately, and the output names carry the
population label.

Two things stop a run that used to proceed, both because the old behaviour was
silently wrong.  A chromosome that looks sex-linked is not analysed until
{\tt --sex-system} says what to do with it (Section~\ref{sec:sexchr}), and an
assembly must be named: {\tt --build}, a {\tt --centromere} file, or
{\tt --no-centromere} if the assembly has no gap to avoid.

\noindent If the automatic window size selection algorithm fails, you can
output the KDEs of the LOD score distribution for multiple window sizes
(without calling ROH) by using the {\tt --winsize-multi} argument, i.e.
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize-multi 30 40 50 60 70 80 90 --out example}
~\\\\
\noindent This will generate KDEs for your inspection.  Once you've chosen a
window size, you should rerun garlic specifying that size.  For example, if you
choose a window size of 60 SNPs, then you would run
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 60 --out example}
~\\\\
\noindent The automatic cutoff is the valley between the two modes of the window LOD score density, pooled over the cohort, and it presumes that the cohort contains runs: a cohort with few or none has a single mode, and what happens then depends on the input.  With likelihood input {\tt garlic} finds no valley and stops, asking for {\tt --lod-cutoff}; with called genotypes it may find a spurious shoulder and call a few percent of every genome (a four-individual simulated cohort with no runs at all was called at $5$--$8\%$).  A cohort of a handful of individuals, or one expected to carry little autozygosity, is therefore a case for a cutoff carried over from a comparable, larger cohort rather than for the automatic rule.

\noindent If you already know what LOD score cutoff to use (say you are
analyzing more individuals from a previously studied population), you can use
the {\tt --lod-cutoff} argument, i.e. if your LOD score cutoff is known to be
2.5 then you would run
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 60 --out example --lod-cutoff 2.5}
~\\\\
\noindent If you already know what size thresholds to use for size
classification (say you are analyzing more individuals from a previously
studied population), you can use the {\tt --size-bounds} argument, i.e. if your
size thresholds are known to be 500000 and 1000000 for the boundaries between
short/med and med/long, respectively, then you would run
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 60 --out example --lod-cutoff 2.5 --size-bounds 500000 1000000}
~\\\\
\noindent Supplying both is also how to reproduce an analysis made with an
earlier version, whose automatic cutoff selection differed; the values to pass
are in that run's log.
~\\\\
\noindent To run the wLOD, you must provide a map file and give the
{\tt --weighted} flag:
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --map example.map.gz --weighted --build hg18 --winsize 60 --out example --error 0.001}
~\\\\
\noindent To count classified genotypes --- deleterious against tolerated, say
--- inside and outside the calls, add {\tt --features} with a file classifying
the sites (Section~\ref{sec:features}):
~\\\\
{\tt garlic --tped example.tped.gz --tfam example.tfam --build hg18 --error 0.001 --winsize 60 --lod-cutoff 2.5 --size-bounds 500000 1000000 --features classes.txt --out example}
~\\\\
\noindent Other command line arguments are described below, and all of them are
listed with their types and defaults in Appendix~\ref{app:flags}.

\section{Statistics implemented}
\label{sec:lod}

We previously advocated the application of a logarithm of the odds (LOD) score measure of autozygosity applied in a sliding-window framework to infer ROH in high-density SNP genotype data \cite[]{PembertonEtAl12:AJHG}. Fundamentally, for SNP $k$ in individual $i$, this method calculates the log-likelihood ratio of observed genotype $G_{i,k}$ under the hypotheses of autozygosity and non-autozygosity, incorporating an assumed genotype error rate $\epsilon$ and population-specific allele frequencies. The LOD score of window $w$ in individual $i$ is then calculated as the sum of the log-likelihood ratios of the $K$ SNPs in the window: 
\begin{equation}
LOD(w,i)= \sum_{k=1}^K \log_{10}\Big(\frac{Pr[G_{i,k} | X_k = 1]}{Pr[G_{i,k} |X_k=0]}\Big).
\end{equation}
Here, $Pr[G_{i,k} |X_k=1]$ is the probability of observing genotype $G_{i,k}$ under the hypothesis of autozygosity ($X_k=1$), and $Pr[G_{i,k} |X_k=0]$ is the probability of observing genotype $G_{i,k}$ under the hypothesis of non-autozygosity ($X_k=0$). For a biallelic locus with alleles $A$ and $B$ that have population frequencies $p_A$ and $p_B$ and a genotype error rate $\epsilon$, the genotype probabilities under the autozygosity and non-autozygosity hypotheses are given in Table 1.

Calculating $LOD(w,i)$ for all windows in all individuals in a given sample set, examination of the distribution of scores shows clear bimodality, with windows in the left-hand mode supporting the hypothesis of non-autozygosity and those in the right-hand mode supporting the hypothesis of autozygosity. The area under the autozygous mode decreases with increasing window size until it disappears, potentially reflecting the window size beyond which window length is often longer than ROH length leading to the inclusion of non-autozygous regions in the $LOD(w,i)$ calculation that mask the presence of autozygosity. A logical window size to use for ROH detection is therefore the largest window size where the distribution of LOD(w,i) is bimodal, with windows defined as autozygous if their $LOD(w,i)$ is greater than the local minimum between the two modes. Contiguous autozygous windows are subsequently joined to define ROH.

If the weighted flag is used, wLOD scores will be calculated as
\begin{align}
wLOD(w,i) &= \sum_{k=1}^K \log_{10}\Big(\frac{Pr[G_{i,k} | X_k = 1]}{Pr[G_{i,k} |X_k=0]}\Big)\times Corr(p_k,[p_1,p_K]) \\ 
&\times Pr[norecombination|[g_{k-1},g_{k}]] \\ 
&\times Pr[nomutation|\mu,[p_{k-1},p_k]],
\end{align}
where
\begin{equation}
Corr(p_k,[p_1,p_K]) = \frac{1}{\sum_1^KLD_{k,i}},
\end{equation}
\begin{equation}
Pr[norecombination|[g_{k-1},g_{k}]] = e^{-2M(g_k-g_{k-1})},
\end{equation}
and
\begin{equation}
Pr[nomutation|\mu,[p_{k-1},p_k]] = e^{-2M\mu(p_k-p_{k-1})}.
\end{equation}
$LD_{k,i}$ is computed as $r^2$ if data are phased and as $HR^2$ if data are unphased. $g_i$ and $p_i$ are the genetic distance and physical distance at marker $i$, respectively.

\section{Program Options}

Using the command line flag {\tt --help}, will print a help dialog with a summary of each command line option.  The full reference is reproduced in Appendix~\ref{app:flags}, which is generated from those same help strings by {\tt make docs} so that it cannot drift from the program.

\subsection{Input Files}

Genotypes are read from a VCF ({\tt --vcf}), a TPED/TFAM pair ({\tt --tped}/{\tt --tfam}, see \\{\tt http://pngu.mgh.harvard.edu/\textasciitilde purcell/plink/data.shtml\#tr}), or, for low-coverage sequence data, genotype likelihoods in beagle format ({\tt --gl-beagle} with {\tt --tfam}; see \S\ref{sec:beagle}).  The three are mutually exclusive.  Either may be read gzipped ({\tt http://www.gzip.org/}) without decompressing first, and a VCF may also be BGZF, as written by {\tt bgzip} or {\tt bcftools}.  Consecutive loci are assumed to be in order with respect to their physical position, and all records for a chromosome must be contiguous --- what {\tt bcftools sort} produces.  If the file contains more than one population, each is analysed separately; see Section~\ref{sec:multipop}.  {\tt --pop} overrides the labels, which for a TPED/TFAM pair are otherwise taken from column 1 of the TFAM.

\subsubsection{VCF input}
\label{sec:vcf}

Biallelic SNVs carrying a {\tt GT} field are used.  Multiallelic sites, indels, symbolic ALT alleles ({\tt *}, {\tt <NON\_REF>}) and records with no {\tt GT} in {\tt FORMAT} are skipped, and the counts are written to the log rather than passed over silently.  The {\tt FILTER} column is reported either way and only acted on under {\tt --vcf-pass-only}, since it records the variant caller's thresholds rather than {\tt garlic}'s.

A VCF states things a TPED cannot, and {\tt garlic} checks them: ploidy is per call, so anything other than a diploid genotype is an error naming the site and the sample; phase is per call, so {\tt --phased} requires {\tt |} everywhere rather than silently mis-reading a {\tt /}; and samples are named in the {\tt \#CHROM} line, so {\tt --tfam} is not accepted alongside {\tt --vcf} --- it could only disagree.  Use {\tt --pop} for population labels; omitting it labels every sample {\tt unknown} and warns, because the allele frequencies really are pooled over all of them.  With {\tt --pop}, each population is analysed separately; see Section~\ref{sec:multipop}.

The counted allele is ALT.  For the same genotypes a TPED counts whichever allele it saw first, so the frequency column may come out as $1-f$ relative to a TPED run.  This changes no ROH call, and a {\tt .freq.gz} file remains interchangeable between the two readers: {\tt readFreqData} compares the {\tt ALLELE} column against the reader's own coding and flips the frequency when they differ.

Genetic map positions are not part of a VCF, so {\tt --weighted} and {\tt --cm} still require {\tt --map}.

Per-genotype genotype qualities are read from the {\tt FORMAT} column with {\tt --gl-type}.  This is the only correct way to use a VCF's {\tt PL} or {\tt GL}: a VCF normalises both so the called genotype's value is exactly $0$, so that single value is $0$ for every call, confident or not, and the information is in how much worse the alternatives are.  {\tt garlic} therefore reads the whole array and computes
\[ P(g) \propto 10^{-\mathrm{PL}_g/10}, \qquad \mathrm{error} = 1 - \frac{P(\mathrm{called})}{\sum_g P(g)}, \]
with {\tt GL} entering the same expression as $\mathrm{PL} = -10\,\mathrm{GL}$.  This reproduces the {\tt GQ} that encodes the same confidence: a {\tt PL} of $(0,30,60)$ gives $0.001$, exactly {\tt GQ} $30$.  If the requested field is absent the run stops and the message names whichever of {\tt GQ}, {\tt PL} and {\tt GL} the record does carry.

\paragraph{Low-coverage sequence data.}  None of the per-genotype quality forms above is suitable for low-coverage sequencing (below roughly $4\times$).  Each reduces to a single, symmetric error rate per genotype --- the probability that the call is wrong, with the wrong call drawn as if at random --- and the dominant error at low depth is not symmetric.  Allelic dropout, where only one of a heterozygote's two alleles is sampled by the reads, turns heterozygotes into homozygotes, and a run of such calls is exactly what autozygosity looks like to the LOD score.  In simulation at $0.5$--$1\times$, a per-genotype error taken from a caller's {\tt GQ} called essentially the whole genome autozygous.  Hard calls with a run-wide {\tt --error} degrade more gracefully, but by about $2\times$ the pooled LOD score density no longer has two modes and the automatic cutoff cannot be located.  The route for such data is {\tt --gl-beagle} (\S\ref{sec:beagle}), which keeps all three genotype likelihoods per site, so that an uncertain site contributes little evidence rather than confident wrong evidence.  How much this matters depends on the signal: in a read-level benchmark of planted consanguinity (runs of $3$--$60$\,Mb, uniform depth, \S\ref{sec:benchmark}) {\tt --vcf --gl-type PL} on {\tt bcftools} calls matched the likelihood input down to $1\times$, while hard calls with {\tt --error} alone lost the cutoff below $4\times$; the per-genotype forms fail where the runs are short or the cohort's evidence is thin, which is where the likelihood input holds.

The companion script {\tt vcf2tped.pl} is deprecated.  It writes a TPED plus a {\tt tgls} file, and a {\tt tgls} file holds one value per genotype, which cannot represent a normalised {\tt PL} or {\tt GL}; {\tt garlic} now rejects such a file rather than computing with it.
\subsubsection{Genotype likelihood input}
\label{sec:beagle}

{\tt --gl-beagle <file>} reads genotype likelihoods in the beagle format that ANGSD writes with {\tt -doGlf 2}: a header line of {\tt marker}, {\tt allele1}, {\tt allele2} and three columns per individual, then one row per site holding $P(\mathrm{reads} \mid \mathrm{allele1/allele1})$, $P(\mathrm{reads} \mid \mathrm{allele1/allele2})$ and $P(\mathrm{reads} \mid \mathrm{allele2/allele2})$.  The marker is {\tt <chromosome>\_<position>}, split at the last underscore so a chromosome name may contain one; alleles may be ANGSD's codes (0--3 for A, C, G, T) or letters.  The file may be gzipped.  Sites must be grouped by chromosome, as in a TPED.

\paragraph{What changes in the analysis.}  With called genotypes the per-site term of the LOD score is $\log_{10} A(g)/N(g)$, where $A$ and $N$ are the genotype distributions under autozygosity and under Hardy-Weinberg (\S\ref{sec:lod}).  With likelihoods it is
\[ \log_{10} \frac{\sum_g L(g)\,A(g)}{\sum_g L(g)\,N(g)}, \]
the same two distributions averaged over the genotype with the reads' likelihood as the weight.  A triplet that names one genotype (1 for it, 0 for the others) gives exactly the called-genotype value, so a beagle file of called genotypes reproduces a TPED run to the byte.  A flat triplet --- a site with no reads --- gives exactly 0, as a missing genotype does.  Only the ratios within a triplet matter, so the file's scaling is irrelevant.  {\tt --error} keeps its meaning and is still required.  In $A$ it is not a per-base or per-genotype error but a mixture weight: an autozygous site is drawn with probability $1-\epsilon$ from the identical-by-descent distribution and with probability $\epsilon$ from Hardy-Weinberg, so $\epsilon$ is the chance that a site inside a true run looks non-autozygous for any reason --- a new mutation, gene conversion, a mis-mapped paralog, a reference artefact, or a genotyping error.  The likelihoods take over only the last of these: a site whose reads do not settle the genotype contributes little either way through $L$, with no help from $\epsilon$, while a site whose reads confidently show a heterozygote inside a run contributes $\log_{10}\epsilon$, and with $\epsilon=0$ a single such site would end the run.  The two are therefore not double-counted, and the value appropriate to likelihood input is, if anything, smaller than the one used for the same data called hard, since calling error has moved out of $\epsilon$ and into $L$.  The per-genotype quality path ({\tt --gl-type}) is what becomes redundant --- it turned a quality into a per-site $\epsilon$, conflating the two roles --- and it is refused with {\tt --gl-beagle}.

Allele frequencies are estimated from the likelihoods by EM under Hardy-Weinberg rather than from called genotypes, per population when there are several.  At low depth frequencies from calls are pulled toward the major allele --- by about $0.04$ at $0.5\times$ and $0.02$ at $2\times$ for alleles below $0.15$ in simulation --- and the EM is not.  A site whose estimate implies less than half a copy of the minor allele among the individuals with reads is treated as fixed and dropped, as a called site with no minor allele is; the EM stops short of $0$ on a monomorphic site, and a site kept at a frequency of $10^{-7}$ contributes a LOD of about $0$ to every window, which is above the usual (negative) automatic cutoff --- an invariant region, or a beagle file written without a site list, was called autozygous in everyone before this rule.  The estimate is written to {\tt <out>.freq.gz} as usual and {\tt --freq-file} overrides it; a column of ANGSD's {\tt .mafs.gz} is a suitable source.  On the shared sex chromosome the frequency comes from the maximum-likelihood calls (a hemizygous call contributing one allele), because the EM treats everyone as diploid; {\tt garlic} warns when that applies.

For everything that reads a genotype rather than a likelihood --- the LD matrix of {\tt --weighted}, {\tt --features}, the site filters --- the maximum-likelihood genotype is used, and a site whose maximum is shared (the flat triplet included) is missing.

\paragraph{Metadata.}  A beagle file carries no sample names (ANGSD writes {\tt Ind0}, {\tt Ind1}, \ldots), so {\tt --tfam} is required and is matched to the columns by position, which is the order of ANGSD's {\tt -b} bam list.  A TFAM with the wrong number of rows is an error.  {\tt --pop} may replace the labels as with a TPED.

\paragraph{Three cautions.}  Run ANGSD on an ascertained site list ({\tt -sites}, or at least {\tt -SNP\_pval}): without one the beagle file holds every covered position, invariant sites included, and at those the EM frequency is set by sequencing error and the window SNP counts no longer mean what {\tt --winsize} assumes.  Give likelihoods, not posteriors.  ANGSD's {\tt -doPost} and {\tt -doGeno} output has a Hardy-Weinberg (or panel) prior already folded in, and feeding it here applies that prior a second time, which biases every site toward the non-autozygous state; {\tt garlic} cannot tell the two apart from the numbers alone.  And a beagle marker carries a physical position only, so {\tt --weighted} and {\tt --cm} still need {\tt --map}.

\paragraph{What it does not fix.}  In simulation the likelihood input holds the called autozygous fraction at its true value down to $2\times$ where called genotypes lose the automatic cutoff.  Below about $2\times$ the evidence in a 60-SNP window is not enough to place a cutoff whatever the per-site model: the automatic cutoff fails or lands far from the truth, and even the best single threshold has a false-positive rate of several percent.  Methods that work there borrow information across windows or from a haplotype reference panel, which this design deliberately does not.  Cohorts of mixed depth are a separate problem --- the cutoff is estimated on windows pooled over all individuals, and the shallow ones are over-called --- addressed by {\tt --stratify-cutoff} (\S\ref{sec:stratify}).

\subsubsection{Cohorts of mixed depth: {\tt --stratify-cutoff}}
\label{sec:stratify}

The automatic LOD score cutoff is the valley between the two modes of the window-LOD density pooled over every individual.  That is right when every individual carries the same evidence per window, and wrong when they do not: an individual at low depth, or with many missing genotypes, has both of its modes compressed toward zero, so a cutoff placed for the cohort calls most of its genome autozygous.  On a simulated genome-wide cohort with thirds at $2\times$, $4\times$ and $30\times$, the pooled cutoff called the $2\times$ third at $1.6$ times the length the same individuals' called genotypes gave, and the $30\times$ third at $1.1$ times.

The location of an individual's non-autozygous LOD mode is a precise measure of the evidence its windows carry: on the bundled cohort it varies by $1.3$ LOD between individuals, against $18$ and $29$ LOD between the three depth classes above.  {\tt --stratify-cutoff} sorts the individuals by that mode, joins neighbours whose modes differ by less than a quarter of the smaller spread into a stratum, and applies the pooled rule within each stratum.  A cohort of uniform evidence is one stratum and gets exactly the pooled cutoff --- the calls are byte-identical, which the test suite checks --- and a mixed cohort splits by depth, each stratum's valley resting on tens of thousands of windows rather than one individual's.  On the simulated cohort above this brought the three thirds to $1.3$, $1.15$ and $1.07$ times the called-genotype length: the pooling artefact is removed, and what remains is the noisier emission at low depth, which no cutoff can undo.

The per-individual mode, spread, stratum and applied cutoff are written to {\tt <out>.ind.tsv}; the {\tt .kde} file is the largest stratum's density; {\tt .params.json} records {\tt lod\_cutoff} as the number of strata and flags it as such.  A stratum of fewer than three individuals does not get a valley of its own --- one or two individuals' windows are too few for the rule, and such a stratum is as likely to be an individual whose lowest substantial mode is in fact its autozygous one (more than half autozygous on the analysed chromosomes; one of the 45 on chromosome 21 of the bundled data) --- and takes the largest stratum's cutoff, with a warning.  A stratum whose density has no valley borrows the other strata's median standardised valley through its own mode and spread.  The flag needs the automatic cutoff and does not subsample.

Without the flag, {\tt garlic} still locates the modes and warns when the cohort would form more than one stratum, naming the strata, so that a mixed cohort analysed with one cutoff is at least a visible choice.

Two approaches were tried and rejected before this one, and are recorded so they are not tried again: standardising every individual's windows by its own mode and spread and pooling the standardised windows --- the non-autozygous spread is set by allele-frequency heterogeneity across windows while the autozygous mode is set by information per site, so the two do not scale together and the standardised density has no common autozygous mode (a reflected-null local-FDR cutoff on it called $55\%$ more genome than the pooled rule on the uniform bundled example, a valley-to-the-right rule $15\%$ more) --- and a valley per individual, which on one individual's windows is too noisy ($10$--$26\%$ more genome called on the same example).

\subsubsection{Reference and mapping bias: {\tt --exclude-regions}}
\label{sec:refbias}

Reads carrying the non-reference allele map less often and with lower quality, so at a true heterozygote the fraction of ALT reads is below one half.  In this model that is a {\em directional} error --- a heterozygote observed as a reference homozygote --- and a run of such calls is what autozygosity looks like.  It has two parts, and they are handled differently.

\paragraph{Regional bias} --- repeats, segmental duplications, structurally divergent segments --- mis-maps reads wholesale, and no per-site model recovers from it.  {\tt --exclude-regions <bed>} drops every site inside the regions of a standard BED file (0-based half-open, further columns ignored, {\tt track}/{\tt browser}/{\tt \#} lines skipped, gzipped or not) before anything is computed: a mappability mask, a repeat annotation, segmental duplications, or any region in which calls are not to be trusted.  It applies on every chromosome, autosomes included; chromosomes the file names that are not in the data are ignored, as a genome-wide mask names them all, and a file that covers no site at all draws a warning, since that usually means the wrong assembly or chromosome naming.  The dropped sites are gone from the frequency file and from every window.  The $F_{ROH}$ denominator is {\em not} reduced by them, unlike {\tt --par}: a run of homozygosity can span a short masked region, and the regions are not a statement about what the genome can carry.  {\tt --freq-only} does not apply the mask and refuses the combination.

\paragraph{Read-level bias} --- the ALT read fraction at heterozygotes falling below one half everywhere --- was simulated with the fraction at $0.45$, $0.40$ and $0.35$ (well beyond what is seen in practice) in half of a cohort, at $1$--$30\times$.  Under the likelihood emission it did not move the calls at $2\times$ and above: the biased half's false-autozygous window rate was $0.0074$ against $0.0034$ for the unbiased half at $2\times$ and at most $0.0004$ from $4\times$, with recall above $0.99$ throughout.  Two corrections were implemented in that simulation --- a dropout confusion matrix on the emission, and likelihoods recomputed at an estimated ALT fraction --- and both reproduced the uncorrected result to the third decimal, so neither is in {\tt garlic}.  What is in {\tt garlic} is the diagnostic: {\tt dropout\_hat} in {\tt <out>.ind.tsv} (\S\ref{sec:beagle}) is $0$ for an unbiased individual and rises with the bias, so an individual whose data differ from the cohort's is visible.

\paragraph{Upstream} is where the rest belongs, and it is worth doing before the data reach {\tt garlic}: map to a reference that carries the alternative alleles (an alt-aware or pangenome mapper, or a population-matched reference); use ANGSD's {\tt -baq 1 -C 50} to down-weight mis-aligned bases, and its {\tt -minMapQ}/{\tt -minQ} filters; filter short reads, whose mapping is the most reference-biased; for ancient DNA, rescale damaged bases ({\tt mapDamage}) or drop transitions ({\tt -rmTrans 1}), which also removes the deamination signal that mimics heterozygosity; and take allele frequencies from a source that is not itself biased --- the likelihood EM here, ANGSD's {\tt -doMaf}, or {\tt --freq-file} from the high-coverage members of the cohort.  A per-individual estimate of the ALT fraction at heterozygotes, if wanted, should be the maximiser of the marginal likelihood over all sites, not the mean ALT fraction at confidently called heterozygotes: conditioning on a confident call selects the sites where both alleles were seen, and in simulation that estimate read $0.44$ at $2\times$ for a true $0.35$.

\subsubsection{Benchmark on simulated low-coverage sequence data}
\label{sec:benchmark}

The low-coverage additions were checked against reads rather than against resampled genotypes (the driver is {\tt bench/bench.py}).  Founder haplotypes for chromosomes 20--22 (GRCh37 lengths, the Bh\'erer sex-averaged map, $N_e = 20\,000$, $\mu = 1.25\times10^{-8}$) were simulated with msprime and transmitted through ped-sim pedigrees with planted consanguinity: five offspring each of full siblings, first cousins and second cousins, and five outbred, twenty individuals in all.  ped-sim's HBD segments are the truth: 31 segments over 11 individuals, 3--65\,Mb per individual.  Each individual's two haplotypes were written out against a random reference carrying the ancestral allele, ART HiSeq 2500 150\,bp paired reads were simulated at $1$, $2$, $4$ and $8\times$, mapped with bwa-mem2, and genotype likelihoods (ANGSD {\tt -GL 1 -doGlf 2}) and hard calls ({\tt bcftools mpileup | call -m -C alleles}) were produced on one shared site list, the founder sites with minor allele frequency at least $0.05$.  {\tt garlic} ran with {\tt --winsize 60 --error 0.001 --size-bounds 500000 1000000} on four inputs: the true genotypes (the ceiling), the hard calls with the run-wide error, the hard calls with {\tt --gl-type PL}, and the beagle file with {\tt --gl-beagle}.  Calls and truth were restricted to the span of the genetic map (118 of 162\,Mb; ped-sim transmits nothing outside it) and scored at base level on runs of at least 1\,Mb, pooled over the twenty individuals.

On the true genotypes {\tt garlic} recovers $0.99$ of the HBD length, and $0.93$ of what it calls lies inside a pedigree segment.  The remaining $0.07$ is not error: it is background autozygosity inherited from the founder population --- heterozygosity inside those segments is $0.00$--$0.03$ against $0.18$--$0.31$ genome-wide --- which the pedigree truth does not contain.  Precision is therefore reported against the {\em attainable} set, the pedigree segments together with the segments called on the true genotypes.

\subsection{Output Files}

{\tt garlic} produces several files as output.  The {\tt .log} file will record the runtime parameters and {\tt .error} will
record any errors that occur; {\tt .error} is created only if something is
actually written to it.  A {\tt .params.json} file records the effective value
of every flag together with the values resolved during the run (selected window
size, LOD cutoff, size class boundaries and random seed), and can be replayed
with {\tt --load-params}.  

A gzipped {\tt .freq} file will be output giving the allele frequencies for each locus in the dataset.  Formatted as
\begin{lstlisting}
CHR	SNP	POS	ALLELE	FREQ
<chr>	<locus ID>	<pos>	<allele>	<freq>
\end{lstlisting}
~\\
With more than one population the file carries one frequency column per population, headed by its label:
\begin{lstlisting}
CHR	SNP	POS	ALLELE	POPA	POPB
<chr>	<locus ID>	<pos>	<allele>	<freq>	<freq>
\end{lstlisting}
~\\
This is the format {\tt --freq-file} reads, so a run's own frequency file can be given back to {\tt garlic} to reproduce that run.  A file with a single frequency column is applied to every population, whatever the column is called, so a frequency file from an earlier version keeps working.  {\tt --freq-only} writes the same file without performing the analysis.
~\\
With {\tt --froh}, a {\tt .froh.tsv} table gives each individual's autozygous
total and the fraction of the genome it covers, one row per individual with the
size classes across the columns.  The denominator is stated in the header, as
are the size-class boundaries actually used, so the fractions can be recomputed
or compared across runs.

\paragraph{The per-individual information report.}  Every run also writes {\tt <out>.ind.tsv} (per population when there are several), one row per individual.  A window's LOD is a sum over the sites in it, and a site that carries no information for an individual --- a missing genotype, or a flat likelihood triplet from a site with no reads --- contributes exactly 0, so two individuals with the same window size can be summing very different amounts of evidence.  The report records, per individual: {\tt n\_sites}, the analysed sites on chromosomes where the individual is diploid; {\tt frac\_informative}, the fraction of them with a called genotype or a non-flat triplet; {\tt snps\_per\_window\_median} and {\tt \_p05}, the median and 5th percentile of informative sites per window; {\tt n\_het\_expected}, the sum of $2p(1-p)$ over the sites used for the two statistics that follow; {\tt het\_obs\_exp}, observed over expected heterozygotes from called (or maximum-likelihood) genotypes; and, for {\tt --gl-beagle} only, {\tt dropout\_hat}, the profile-likelihood estimate of the probability that a true heterozygote was observed as a homozygote.  The last two are taken over the sites in windows whose LOD is below 0 --- a cutoff-free stand-in for ``not autozygous'', chosen so the report can be computed while the genotype matrices are still resident rather than holding them until the cutoff is known --- and so are not confounded by the individual's own autozygosity.  {\tt garlic} warns when an individual's 5th percentile falls below half the window size.

Two cautions on reading it.  {\tt het\_obs\_exp} is the ordinary sample-quality statistic for called data; it is {\em not} a low-depth estimator --- at $2\times$ it reads about $0.5$ with no bias at all, because the maximum-likelihood call at one or two reads is a homozygote.  {\tt dropout\_hat}, which models the reads rather than the call, reads $0$ there, and rises with allelic dropout or reference bias (about $0.07$ at $4\times$ for an ALT read fraction of $0.35$ at heterozygotes, in simulation).  Both have sampling noise of roughly $1/\sqrt{\tt n\_het\_expected}$ --- a few hundredths on one chromosome, a few thousandths genome-wide --- so read them against the cohort rather than as absolutes.  Neither corrects anything: in simulation, read-level reference bias did not move the calls at $2\times$ and above, so no correction is applied; the report is there so that an individual whose data differ from the rest of the cohort is visible.

There are two things that fraction can be taken of, and {\tt
--froh-denominator} chooses between them.  {\tt analyzed}, the default and what
{\tt garlic} has always done, is the span the markers cover: from the first to
the last locus of each analysed chromosome, less the centromere and any region
excluded with {\tt --par}.  It is what a marker set can support on its own, and
it moves with the marker set, so F$_{\mathrm{ROH}}$ from two different arrays
are not directly comparable.  {\tt assembly} is the full length of each
analysed chromosome with nothing subtracted --- not the centromere, not the
pseudoautosomal regions, not the part beyond the outermost marker.  That is
what published F$_{\mathrm{ROH}}$ denominators are: the hg19 autosomes sum to
2,881,033,286\,bp and chrX is 155,270,560\,bp, which are the 2881.03\,Mb and
155.27\,Mb of \citet{CotterEtAl24}.  On the bundled example data the two differ
by about 5\%.

The sum is over the chromosomes that were {\em analysed}, and the assembly
supplies each one's length --- it is not a sum over the assembly.  A run
restricted with {\tt --chr} is divided by those chromosomes alone, and a
contig that carries no data is never looked up, which is why a VCF full of
decoys, unplaced scaffolds and alternate haplotypes needs no filtering here.
A chromosome that was analysed and has no length available stops the run rather
than falling back to its marker span, since mixing the two conventions across
chromosomes gives a denominator that is neither.

Lengths come from {\tt --chr-lengths}, from {\tt --build}, or from a VCF's
{\tt \#\#contig} header, in that order of precedence.  {\tt --chr-lengths} takes
two whitespace-separated columns, chromosome and length, and also accepts a
{\tt samtools faidx} {\tt .fai} unchanged --- its first two columns are
already name and length.  It is the way to use this mode on a non-human
assembly and on TPED input, where nothing in the data states a length.  The
built-in tables are the GRC assembly reports' own numbers, recorded with their
source in {\tt centromeres/chr\_lengths.txt}.  {\tt assembly} is refused with
{\tt --cm}: a chromosome's length in base pairs is not its length in
centimorgans.

Whenever lengths are available, {\tt garlic} checks that no marker lies beyond
the end of the chromosome it is on.  This is how a wrong {\tt --build}
announces itself, which nothing else in the program can detect --- and it
matters in either mode, because the centromere and pseudoautosomal coordinates
in use came from that same assembly.  Under {\tt assembly} a violation stops
the run, since those lengths are the denominator; under {\tt analyzed} they
feed nothing, so it is a warning.  Where a VCF header and {\tt --build} both
state a length and disagree, one of them is not this assembly and {\tt garlic}
says so rather than picking.

Kernel density estimation of the LOD score distribution is output to {\tt .<winsize>SNPs.kde} formatted as
\begin{lstlisting}
<LOD score> <density>
\end{lstlisting}
~\\
ROH calls are output to {\tt .roh.bed}, which are formatted as UCSC BED files. There is one track per individual (all individuals in the same file) and the data are formatted as
\begin{lstlisting}
<chr> <ROH start> <ROH end> <size class> <ROH length> <placeholder> <placeholder> <placeholder> <RGB track color>
\end{lstlisting}
~\\
\noindent Following the BED specification, {\tt <ROH start>} is 0-based and
{\tt <ROH end>} is exclusive, so {\tt <ROH end>} minus {\tt <ROH start>}
equals {\tt <ROH length>}.  Note that under {\tt --cm} the boundaries remain
physical positions while {\tt <ROH length>} is reported in cM, so that identity
does not hold in that mode.  Versions before this one wrote {\tt <ROH start>}
as a 1-based position, making every tract appear one base short in a genome
browser; coordinates from those versions are shifted by one relative to these.
~\\
When requested, raw LOD scores are also output.  This file contains one row per individual (corresponding to the order in the {\tt .tfam} file), and LOD scores for each window are given on the columns.
\begin{lstlisting}
<LOD score window 1> <LOD score window 2> ... <LOD score window N>
\end{lstlisting}
~\\

\subsubsection{{\tt --out}}

Use {\tt --out <string>} to provide a base name for an output file.  This will be used in place of {\tt <outfile>} above.  Default value is {\tt outfile}.  

\subsection{Multiple populations}
\label{sec:multipop}

The LOD score is parameterised by population allele frequency, so pooling
distinct populations inflates heterozygosity relative to any one of them and
biases the ratio for all of them.  When the input contains more than one
population label, {\tt garlic} therefore analyses each population separately
and in turn.  Each receives

\begin{itemize}
\item allele frequencies computed from its own individuals;
\item its own site filtering, so a site that is monomorphic in one population
      but polymorphic in another is dropped where it is uninformative;
\item its own automatically selected window size, LOD score cutoff and
      size-class boundaries;
\item its own random number stream, derived from {\tt --seed}, so its result
      does not depend on how many populations preceded it in the file.
\end{itemize}

\noindent A value given explicitly on the command line is not re-derived, so
{\tt --winsize}, {\tt --overlap-frac}, {\tt --lod-cutoff} and
{\tt --size-bounds} apply to every population.

The consequence worth stating plainly is that analysing several populations
together gives each of them exactly what analysing it alone would give.  The
populations do not interact; running them in one command is a convenience, not
a joint model.

Populations are processed one at a time rather than together, so peak memory
is bounded by the largest population rather than by their sum.

\subsubsection{Where the labels come from}

For a TPED/TFAM pair the label is column 1 of the TFAM.  {\bf PLINK calls that
column the family ID}, and in many files it is one family --- sometimes one
sample --- per value.  Such a file will produce one analysis per family, which
is almost certainly not what was intended.  {\tt garlic} warns when the
smallest population has fewer than five individuals, and again when there are
more than two populations per individual on average, but it cannot tell the two
situations apart with certainty.  Use {\tt --pop} to supply real population
labels, or {\tt --pool-populations} to ignore them.

A VCF carries no population labels, so {\tt --pop} is the only way to set them;
without it every sample is labelled {\tt unknown} and the analysis is pooled.

\subsubsection{Output files}

With one population the output file names are unchanged.  With more than one,
the population label is inserted before the extension:
{\tt <out>.<POP>.roh.bed}, {\tt <out>.<POP>.froh.tsv}, {\tt <out>.<POP>.ind.tsv},
{\tt <out>.<POP>.params.json} and {\tt <out>.<POP>.<winsize>SNPs.kde}.  The
{\tt .log}, {\tt .error} and {\tt .freq.gz} files are written once for the
whole run.

\subsubsection{{\tt --pool-populations}}

This flag makes {\tt garlic} ignore the labels and analyse every individual
together, which is what it did before per-population analysis existed.  Allele
frequencies, the LOD score cutoff, the window size and the size classes are
then computed over every sample at once, and the unlabelled output names are
restored.  Use it when the labels are not populations, or to reproduce a run
from an earlier version.  The {\tt .froh.tsv} header records that pooling
happened, and so does {\tt .params.json}.

\subsubsection{When a population cannot be analysed}

A small population can fail size-class fitting or cutoff selection where a
pooled fit would have succeeded.  {\tt garlic} reports which population failed
and stops, rather than writing a partial set of results that looks complete.
Supplying {\tt --size-bounds} or {\tt --lod-cutoff} avoids the automatic step
that failed.

\subsection{Sex chromosomes}
\label{sec:sexchr}

A hemizygous genotype is written as a homozygous call, so a sex chromosome
analysed as an autosome is called as one run spanning its whole length in
every heterogametic individual, and any $F_{ROH}$ computed from that is
inflated.  {\tt garlic} therefore refuses to analyse a chromosome that looks
sex-linked until it is told what to do with it.

\subsubsection{Declaring the system}

{\tt --sex-system} takes {\tt xy}, {\tt zw} or {\tt none}.  It supplies the one
thing no amount of genotype data can: which sex \emph{code} is heterogametic.
PLINK codes 1 male and 2 female whatever the species' sex determination system
is, so in a ZW species the \emph{homogametic} sex is the one coded 1.  Leaving
the flag unset is not the same as {\tt none}: unset means nothing has been said
and the run stops, while {\tt none} asserts that every chromosome is diploid in
every individual.

The conventional names follow from the system --- X and Y under {\tt xy}, Z and
W under {\tt zw}, plus M or MT for the mitochondrion.  A chromosome named
anything else is declared explicitly with {\tt --sex-chr} (diploid in the
homogametic sex), {\tt --sex-chr-degenerate} (carried only by the heterogametic
sex) or {\tt --haploid-chr}.  A chromosome's role does not depend on the system:
X and Z are both the shared chromosome, Y and W both the degenerate one.  Only
the shared chromosome is analysed; the others cannot carry a run of homozygosity
in anybody and are dropped with a log line.

The numbers 23, 24, 25 and 26 are X, Y, the pseudoautosomal region and the
mitochondrion under PLINK's coding of \emph{human} data, and ordinary autosomes
in any species with that many chromosomes.  {\tt garlic} resolves them only when
{\tt --build} names a human assembly, which is already the user asserting human
coordinates; without one it refuses rather than picking a reading.

\subsubsection{What the analysis does}

Allele frequencies on the shared sex chromosome are computed over
\emph{everyone}, with the heterogametic sex contributing one allele and the
homogametic sex two.  Runs of homozygosity are then called only in the
individuals who are diploid there.  The LOD score cutoff, the window size and
the size-class boundaries are estimated on the autosomes and applied to the sex
chromosome; {\tt garlic} reports what the sex chromosome's own windows would
have given, so the assumption is visible.  This follows
\citet{CotterEtAl24} and, for the cutoff, the reason they give: one chromosome's
windows from part of a cohort usually cannot locate a second minimum in the
density.

That is the default rather than the only option.  A cohort where the reported
diagnostic shows the autosomal cutoff is badly placed on the sex chromosome can
be given another with {\tt --sexchr-lod-cutoff}, and a different window size
with {\tt --sexchr-winsize}; both apply to the shared sex chromosome alone and
leave every autosomal call exactly where it was.  They are values you supply
rather than a switch asking {\tt garlic} to re-estimate, because the reason the
autosomal cutoff is the default is that the estimate on that chromosome usually
fails --- the diagnostic is where the value comes from.  A LOD score cutoff
belongs to the window size it was estimated at, so {\tt --sexchr-winsize}
requires {\tt --sexchr-lod-cutoff}: the autosomal cutoff no longer describes
windows of another size.  Both are recorded in {\tt <out>.params.json} as
{\tt sexchr\_winsize} and {\tt sexchr\_lod\_cutoff}, which hold the values that
were applied whether or not the flags were given, so the record says what
happened without a reader having to reconstruct it from the command line.

A half call carries no genotype, which is what the rest of the pipeline needs
to know about it.  The LOD score takes its default branch for one, so
{\tt --tgls} and a VCF's {\tt GQ}, {\tt PL} or {\tt GL} need no special
handling --- the per-genotype error rate is never read there.  That last point
is load-bearing for a hemizygous VCF: a haploid {\tt PL} array holds one value
per allele, two at a biallelic site rather than the three a diploid site has,
and it is never parsed.  Both LD statistics behind {\tt --weighted} skip an
uncalled genotype too, so the LD matrix on the shared sex chromosome is
estimated among the individuals who are diploid there; under
{\tt --ld-subsample} the subsample for that chromosome is drawn from those
individuals, so the number requested is the number that informs it.

Who is diploid there is established by a check that always runs.  Each
individual's heterozygosity on that chromosome is compared against
{\tt --het-rate-bounds} (0.02 and 0.10 by default): below the first it reads as
hemizygous, above the second as diploid, and between them as ambiguous, in which
case the individual is neither called there nor counted towards the allele
frequency.  A recorded sex is checked against this and an unrecorded one is
inferred from it.  The per-individual result is written to
{\tt <out>.sexcheck.tsv}.  Heterozygous calls in an individual with one copy of
the chromosome are impossible by construction, so they are counted and
discarded; if more than half the individuals with a recorded sex contradict it,
{\tt garlic} stops, because that means either {\tt --sex-system} is inverted or
the chromosome was called as diploid --- and the alternative is discarding every
one of those calls silently.

$F_{ROH}$ is reported separately for the autosomes and for the sex chromosome,
each with its own denominator, and is {\tt NA} rather than zero for an
individual that cannot be autozygous there.  The two are not summed: the X
coalesces faster than the autosomes and carries more homozygosity at the same
level of consanguinity, so they are quantities to compare rather than to pool.

\subsubsection{Pseudoautosomal regions}

A pseudoautosomal region is diploid in both sexes.  {\tt --par} takes one or
more {\tt <chr>:<start>-<end>} intervals and {\tt --par-file} reads them from a
file; both accept any number of regions per chromosome --- humans have two ---
and the two flags accumulate.  Unlike {\tt --centromere}, repeated rows for one
chromosome add a region rather than replacing one.  The loci inside are dropped,
each region's count is reported separately, and a region that matches no locus
warns by name.

They are identified by coordinates on a declared sex chromosome and never by a
chromosome code, because PLINK's 25 is an ordinary autosome in most species.

For the human X, {\tt --build} supplies them: the coordinates are the Genome
Reference Consortium's own definition for that assembly, recorded with their
source in {\tt centromeres/par\_regions.txt}, and they are filed under whatever
the data calls that chromosome --- {\tt chrX} in one file and {\tt 23} in the
next.  Naming any region with {\tt --par} replaces them, and {\tt --par none}
keeps them all.  No table is supplied for a shared sex chromosome that is not
the human X, since a species' own coordinates are not the assembly's.

Running without them --- on a non-human assembly, or under {\tt --par none} ---
has a bounded cost, which is worth knowing rather than discovering.  The heterogametic sex's genotypes in the pseudoautosomal region
are recoded as hemizygous along with the rest of the chromosome, so their real
heterozygous calls there are counted as impossible and discarded --- inflating
{\tt n\_het\_recoded} by roughly that region's share of the markers, about 1--2\%
of the human X --- and their contribution to the allele frequency in it is
biased, because dropping heterozygotes while keeping homozygotes is not a random
thinning.  Both are bounded by the total pseudoautosomal share of the
chromosome, which is the quantity that grows in a species that has several.

\subsubsection{Chromosome names}

Names are matched case-insensitively and ignoring a leading {\tt chr}, so
{\tt chrX}, {\tt chrx}, {\tt CHRX}, {\tt X} and {\tt x} are one chromosome, and
so are {\tt 1}, {\tt 01} and {\tt chr1}.  Output keeps whatever the input said.
Two chromosomes in one file whose names differ only that way are an error, and
so is the same name appearing twice, which means one chromosome whose rows are
not contiguous --- {\tt garlic} starts a new chromosome whenever the chromosome
column changes and would otherwise analyse it as two.

\subsection{Counting classified genotypes}
\label{sec:features}

\noindent A common use of a set of runs of homozygosity is to ask whether
genotypes of some class --- deleterious, non-synonymous, whatever an annotation
supplies --- are found inside them more often than outside. {\tt --features}
does that counting as part of the run that makes the calls, and writes
{\tt <out>.counts.tsv}.

The classification is a file of four whitespace-separated columns, the
chromosome, the position, the allele that carries the classification, and the
class label:

\begin{lstlisting}
#chr   pos        allele  class
chr21  15481365   T       probably_damaging
chr21  15481365   T       nonsynonymous
21     15502312   A       benign
\end{lstlisting}

\noindent The label is arbitrary text and there may be any number of distinct
labels. A site may appear more than once, as the first two rows above do, so
two annotation schemes can classify the same variant; the categories are not
required to be mutually exclusive. The same class twice at one site is an
error rather than a silent overwrite. Chromosome names are matched ignoring
case and a {\tt chr} prefix, and the allele is compared as a string, so an
indel allele from a sequenced call set works as well as a single base.

For every individual and every class, the table gives three numbers in each
bucket: {\tt hom}, homozygous for the classified allele; {\tt het}, carrying
one copy; and {\tt n}, the classified sites at which that individual has a
genotype at all. The last is the denominator, and it is what separates ``more
deleterious homozygotes inside runs'' from ``more sites inside runs''. The
buckets are the size classes the population was analysed with, then
{\tt NONE}, then {\tt UNASSESSED}, then {\tt ALL}; the count inside runs of
homozygosity is {\tt ALL} less {\tt NONE} less {\tt UNASSESSED}.

{\tt UNASSESSED} is a site where no run could have been called for anybody: a
chromosome that was not analysed, one carrying fewer than two loci, an
assembly gap, a region excluded by {\tt --par}, or a position outside the span
the markers cover. It is kept apart from {\tt NONE} because folding the two
together inflates the outside-runs count by however much of the genome the
analysis left out. Two further columns account for the rest of each
individual's classified sites: {\tt n\_hemi}, sites on a chromosome where that
individual is not diploid, and {\tt n\_missing}, sites it has no call for.
Every classified row lands in exactly one of those places, so
$\sum {\tt ALL\_n} + {\tt n\_missing} + {\tt n\_hemi}$ is the same for every
individual the genotypes covered.

The genotypes are read from the file, raw. They are deliberately not the
filtered matrix {\tt garlic} calls from: that has had monomorphic sites
dropped population by population, has been pruned by {\tt --chr} and
{\tt --autosomes-only} and has had excluded regions removed, and counting from
it would discard exactly the rare functional sites the question is about. By
default the input the run was called from is read a second time. When the
classified variants live elsewhere --- calls from a genotyping array,
classifications from sequencing --- give that file with
{\tt --tped-counting} and {\tt --tfam-counting}, or with {\tt --vcf-counting};
the two files need not share a single site. Individuals are matched by
identifier, and one present in only one of the two files is reported rather
than counted as having no runs.

\subsubsection{Counting against calls that already exist}

\noindent {\tt --roh-file} counts against a {\tt .roh.bed} written earlier, or
published, instead of calling anything. It needs {\tt --features} and one of
the counting genotype flags, and it accepts no calling input.

Less is knowable this way, and the table says so rather than leaving it to be
inferred. A {\tt .roh.bed} records where the runs are; it does not record which
chromosomes were analysed, how far the markers reached, or what the size class
letters mean. So nothing can be marked {\tt UNASSESSED}, every site outside a
run is {\tt NONE}, and the size class boundaries are reported as unknown.
Counting inside the run that makes the calls knows all three, which is the
reason to prefer it where there is a choice.

One wrinkle is worth knowing about. Version 1.1.6a was released with two
different {\tt chromStart} conventions under the same version string, so the
version in a file's track line does not say which one it uses. {\tt garlic}
works it out from the file instead: a conforming BED has
${\tt chromEnd} - {\tt chromStart}$ equal to the length column, and the older
convention has it one less. The answer is counted over every call rather than
taken from the first, a file that is half each is refused as two files
concatenated, and the convention that was used is recorded in the output
header. Under {\tt --cm} the length column is a genetic distance and settles
nothing; that case warns and names its assumption.

\subsection{Controlling GARLIC}

\noindent The remaining flags control window construction, LOD score
calculation, cutoff selection, size classification, reproducibility and
output. They are listed with their types and defaults in
Appendix~\ref{app:flags}, which {\tt make docs} generates from {\tt garlic}'s
own help strings.  This section previously restated them by hand, which is how
